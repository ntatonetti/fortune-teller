# Real sound effects instead of spoken "creak and whirr"

## Problem

Claude sometimes writes sound effects into Madame Mechanika's lines ("*creak*... whirrr... ah, a visitor"), and ElevenLabs reads them aloud. Nothing in the stock lines does this. It comes from the persona ("made of brass gears") and the greeting prompt ("you are creaking awake"). Meanwhile the browser already plays synthesized machine sounds at the right moments (`static/js/sound.js`), and they're thin.

## Goal

- She never says sound effects. Her speech and subtitles contain only words.
- The machine sounds (`creak`, `grind`, `whir`, `coin`, `ratchet`) are real recorded-quality clips generated by the ElevenLabs Sound Effects API.
- Everything keeps working with no ElevenLabs key, or when generation fails: she falls back to the current synth sounds.

Non-goals: letting Claude cue effects mid-sentence; replacing the music box, bells, shimmer, or clock tick.

## Design

### 1. Clean speech (server)

**Prompt.** In `server/oracle.py`:
- Add to `PERSONA`: "Your words are spoken aloud by your voice box. Never write sound effects, noises, or stage directions (no creak, whirr, clank, no asterisks or brackets). Your machinery makes its own sounds."
- Change the greeting prompt's "you are creaking awake" to "you are stirring awake".

**Scrubber.** New function `scrub_spoken(text: str) -> str` in `server/oracle.py`, applied to `Greeting.greeting`, `Fortune.spoken`, and `Fortune.card_text` before they're returned (so TTS, subtitles and the printed ticket all match). It:
- Removes asides wrapped in `*...*`, `[...]`, or `(...)`.
- Removes sound words only when they stand as their own fragment: bounded on both sides by the start/end of text or punctuation (`.`, `,`, `!`, `?`, `…`, `—`, `-`), optionally repeated ("Creak, creak..."). Sound words: creak, whir/whirr, clank, clink, click, clack, tick, tock, grind, bzzt, hiss, ding, clunk, with stretched spellings ("whirrrr", "creeeak"). A sound word inside an ordinary sentence ("the gears whir in the dark") is left alone, and words that merely contain one ("ticket") are never touched.
- Tidies the result: collapses doubled spaces and orphaned punctuation, strips leading punctuation, and capitalizes the first letter.
- If scrubbing leaves nothing, returns the original text unchanged (better a stray "creak" than silence).

### 2. Effect library (server)

New module `server/sfx.py`:

- `EFFECTS`: a dict of effect name → list of variants, each variant a `(prompt, duration_seconds)` pair. Two or three variants per effect so repeats don't sound identical:
  - `creak`: an old brass servo/hinge creak, ~1 s
  - `grind`: clockwork gears grinding and catching, ~2 s
  - `whir`: steady busy clockwork machinery hum, loopable, ~4 s
  - `coin`: a coin dropping into a metal slot and clunking, ~1.5 s
  - `ratchet`: a ticket being ratcheted out of an old machine, ~2 s
- `prewarm()`: for each variant whose file is missing, call `POST https://api.elevenlabs.io/v1/sound-generation` with `text`, `duration_seconds`, and `prompt_influence` (~0.5), and `loop: true` for `whir` if the current model supports it (check the API docs during implementation; if not, the browser crossfades the loop). Save as `data/sfx/<name>-<i>-<hash>.mp3`, where `<hash>` is a short hash of the prompt and duration, so editing a prompt regenerates that clip; deleting a file also regenerates it.
- Needs only `ELEVENLABS_API_KEY` (no voice ID). Reuses the voice module's concurrency limit and 429 retry approach. Any failure is logged and that variant is skipped.
- `available() -> dict[str, list[str]]`: effect name → URLs of the clips present on disk.

`server/config.py` gets `SFX_DIR = ROOT / "data" / "sfx"`. `server/app.py` runs `sfx.prewarm()` alongside `voice.prewarm()` in `lifespan`, serves clips at `/api/sfx/<file>` (same path-safety check as `cached_path`), and adds `"sfx": sfx.available()` to `/api/config`.

Clips are generated once and then served from disk, so the party Wi-Fi doesn't affect them. Cost is roughly 15 one-time generations.

### 3. Playback (browser)

In `static/js/sound.js`:

- `loadEffects(map)`: given the `sfx` map from `/api/config`, fetch and decode every clip into `AudioBuffer`s. Called from `main.js` once config loads. Effects with no clips simply aren't in the map.
- `creak()`, `grind(duration, vol)`, `whir(on)`, `coin()`, `ratchet(seconds)`: if buffers exist for that effect, play a random variant (never the same one twice in a row); otherwise run the existing synth code unchanged. Signatures don't change, so call sites in `main.js` stay the same.
  - `grind(duration)` plays the clip for `duration` seconds with a short fade-out.
  - `ratchet(seconds)` likewise.
  - `whir(on)` loops its clip (`AudioBufferSourceNode.loop`) and fades in/out over ~0.15 s, as the synth version does now.
- Clips go into the existing `this.sfx` bus, which already bypasses the phonograph filter and the jaw analyser, so a creak never moves her mouth. Volume arguments scale the clip gain; a per-effect base gain balances the clips against the voice.

### 4. Testing

- `tests/test_server.py`: `scrub_spoken` cases: asterisk/bracket asides, a leading "Creak... whirrr..." fragment, "Creak, creak!", a sound word inside a real sentence left alone, "ticket" untouched, text that is only a sound effect returning the original.
- `sfx.prewarm()` with no key does nothing and `available()` is empty; with a mocked failing request it logs, skips, and doesn't raise; existing files aren't regenerated.
- `/api/config` includes the `sfx` map.
- Manual listen in Chrome: **W** to wake (creak + grind), **Space** for the coin, the consult phase (whir), **G** for a glitch (grind), and a full reading through to the ticket (ratchet). Then again with `ELEVENLABS_API_KEY` blank to confirm the synth fallback.

### 5. Docs

README "Keys and voices" section: one paragraph saying the same ElevenLabs key also generates the machine sound effects once at startup into `data/sfx/`, and how to regenerate one (delete the file). `data/sfx/` is already covered by the `data/` rule in `.gitignore`.

## Revision (2026-10-28): clips are committed, not generated at startup

The clips are generated once by `scripts/make_sfx.py` into `assets/sfx/` (`config.SFX_DIR`) and committed to the repo. The server no longer calls ElevenLabs for sound effects at startup; it only serves what's in `assets/sfx/`. The script requests only missing clips, removes clips left over from old prompts (`sfx.prune()`), and exits non-zero if any clip is still missing. This replaces the startup `prewarm()` and the `data/sfx/` cache described above.
